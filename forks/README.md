# forks/ - libraries that fork ONNX Runtime kernels

These two libraries are not standalone custom ops in the ABI sense: their kernels are copies of ORT CUDA kernels (modified for
the Qwen3.8 decode graph), so they include ORT **private** headers (`core/common/status.h`, `core/providers/cuda/cuda_common.h`,
`contrib_ops/cpu/bert/dynamic_sparse_attention_parameters.h`, `cu_inc/*.cuh`, ...), the `onnxruntime_config.h` generated by an ORT
build, and link ORT's static libraries (`libonnxruntime_common.a` and the `_deps` libraries it needs). They register a normal
custom-op domain through `RegisterCustomOps` and are loaded like any other library (`custom_ops_libraries`), but they only build
against a matching ORT source + build tree, and only with `-DQWEN38_BUILD_ORT_FORKS=ON`.

| library | domain / op | sources | forked from |
| --- | --- | --- | --- |
| `libqwen_guarded_dsa_r2_v12.so` | `qwen.static` / `GuardedDSA` | `guarded_dsa_r2/` | `contrib_ops/cuda/bert/dynamic_sparse_attention_impl.cu` (guarded dynamic sparse attention with a 2-row chain, `ZeroFlagsKernel` patch, and BF16 / per-channel INT8 / per-channel FP8 E4M3FN KV cache support via `k_scale` and `v_scale` attributes) |
| `libqwen_packed_qsa_indexer_v11.so` | `qwen.capture` / `PackedQSAIndexer` | `packed_qsa_v11/` | `contrib_ops/cuda/sparse/packed_sparse_attention_indexer_{impl.cu,impl.h,common.h}`, `sparse_attention_indexer_{common.h,device_math.cuh}` (built with `-DPACKED_QSA_EXACT_FLOAT_STATE`) |

## ORT commits they fork from

* Kernel sources: ORT PR #33094 (local branch `pr33094`), head `c6501ff96daf1f682d4bf17dea543ce1a64b2df4` ("Fix Qwen NVFP4 CI test APIs and review
  formatting"), which sits on ORT `main` at `6e0f154e32` (Oct 10 2026). `guarded_dsa_r2.cu` differs from that branch's
  `dynamic_sparse_attention_impl.cu` by ~140 lines (2-row chain, per-row error flags, capture-safe launch); the packed QSA files are the
  PR's packed indexer (originally ORT #32618, `3188a2eeb1`) with the v11 exact-float-state changes.
* Private headers and build tree used for the reproduction: ORT `504238c6da7c61e6bb5e4042eb503fbbce868b71`
  ("Support offline NVFP4 QMoE weights through weights_prepacked", Oct 5 2026), CUDA plugin EP configuration (`BUILD_CUDA_EP_AS_PLUGIN`),
  Release, SM 9.0a, CUDA 13.0, FP4 QMoE + FlashAttention + memory-efficient attention ON (the compile definitions in `CMakeLists.txt`
  are those of ORT's `onnxruntime_providers_cuda_plugin` target of that build). The 13 local working-tree patches of the research
  build (cast/conv/gather_block_quantized/moe_gemv_fp4/dynamic_sparse_attention) are not needed: a rebuild from a clean
  `git archive 504238c6` source gives identical SASS and PTX.

## Build

```bash
# 1. an ORT build tree of that revision (any target that produces libonnxruntime_common.a and the generated headers; the research
#    build was `cmake -G Ninja` Release with the target `onnxruntime_providers_cuda_plugin`, CUDA 13.0, SM 90a).
# 2. this repository:
cmake -S . -B build -DORT_INCLUDE_DIR=<ORT_SOURCE_DIR>/include/onnxruntime/core/session \
      -DQWEN38_BUILD_ORT_FORKS=ON \
      -DORT_SOURCE_DIR=<ORT source at 504238c6> \
      -DORT_BUILD_DIR=<ORT>/build/Release \
      -DORT_DEPS_DIR=<third-party sources, optional>
cmake --build build --target qwen_guarded_dsa_r2_v12 qwen_packed_qsa_indexer_v11
```

* `ORT_SOURCE_DIR`: ORT source checkout (needs `include/`, `onnxruntime/core`, `onnxruntime/contrib_ops`).
* `ORT_BUILD_DIR`: the Release build directory with `onnxruntime_config.h`, `libonnxruntime_common.a`, and `_deps/{onnx-build,pytorch_cpuinfo-build,cpp_client_telemetry-build,matsdk_curl-build,matsdk_mbedtls-build}`.
* `ORT_DEPS_DIR` (optional): directory with the third-party sources in the upper-case `FETCHCONTENT_SOURCE_DIR_*` layout
  (`ABSEIL_CPP`, `CUTLASS`, `DEEP_GEMM`, `DATE`, `EIGEN3`, `FLATBUFFERS`, `GSL`, `MP11`, `ONNX`, `PROTOBUF`, `PYTORCH_CPUINFO`,
  `SAFEINT`, `CUDNN_FRONTEND`); when empty the `<ORT_BUILD_DIR>/_deps/<name>-src` directories of a stock ORT build are used.
* The CUDA toolkit is taken from `CMAKE_CUDA_COMPILER` and must be the one the ORT tree was built with.

`cuda_runtime_status.cc` provides the one ORT symbol (`CudaCall<cudaError,...>`) that the forks need from the CUDA provider without linking it;
the version script (`*.exports`) exports only `RegisterCustomOps`, so the ORT static libraries stay hidden inside the library.

## Longer-term

The strategy is to remove these forks: make the 2-row chain / per-row validation a feature of ORT's `DynamicSparseAttention` and
`PackedSparseAttentionIndexer` contrib ops (upstream PRs), then the package can use the stock ops.
